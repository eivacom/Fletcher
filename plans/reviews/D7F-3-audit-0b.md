- **Rung 6(e) (`RunClosingFromInside(kDestroyFromCallback)`, test:1967-2059): LAWFUL.** Amended L9 says: "when ... the `SubscriberArrow` is destroyed, from inside the subscription's own batch callback, ... the call does not wait for that subscription's batches ... any full windows already queued are delivered first, in order, then the `kClosing` batch". The test matches this. `at_unsubscribe_return == 1` means nothing is delivered inside `~SubscriberArrow`. The expected order is `kTimeout`(0), then the queued `kRowLimit`(1,2), then `kClosing`(3), all on the batch thread, with depth ≤ 1. The `DeliveryLog` outlives every delivery (`WaitFor(3)`, `WaitAllReturned`), which matches "The callback must outlive those batches". **2026-09-05:** spec §6.5 says "destroying any seam object ... requires that no delivery on that instance is in flight on this thread". The destruction runs inside a `kTimeout` batch callback, on the batch thread, which carries no provider delivery. The test chose the timeout window for exactly that reason (comment at :1983-1984), so it never requires the forbidden state on either tree. There is now a test for Ruling (1), which closes my earlier gap.
- **`FailedBatchedSubscribeReleasesItsCallback` (test:2297-2328): LAWFUL in what it requires, UNMOORED in its subject.** Its premise is a batched `Subscribe` from inside a per-row delivery, refused with `kReentrantCall`. Spec §6.6 (2026-09-05) requires that refusal: "`Subscribe` ... throw `PubSubError(kReentrantCall)` ... when issued from inside a delivery callback on the same provider instance and the same thread". The test calls the refused method and asserts the refusal, which is lawful. Its subject is that a failed `Subscribe` releases its callback and leaves no batch thread behind. No law or ruling covers that. L10 and L11 are the nearest, but they speak of a live batcher. It is a lawful hygiene property, but it pins something the law does not state. Either d7 gains a line (for example, "a refused Subscribe leaves nothing running") or the guard is recorded as pinning code-review S1.
