# Domain 2: Row encoding and the envelope

> **Specified.** The owner confirmed these laws on 2026-11-10 ([RIX-rulings.md](../../plans/RIX-rulings.md), "Yes on all accounts"). A change to a law needs
> an owner ruling, recorded in a decision of record.

## 1. Intent

**Owns:** the bytes of one row and of one envelope, and nothing about how they travel.
- The **positional row format** and every encoder/decoder of it: `PositionalWriter`/`PositionalReader`
  (`pio`), `Codec` (`arrow-bridge/.../codec.hpp`), `BatchDecoder`'s decoding (`batch_decoder.hpp`).
- The **Arrow-type → payload mapping** (which bytes each Arrow type becomes). The proto → Arrow
  mapping is generated by `protoc/src/type_mapper.cpp` and is shared with domain 1 (open question Q1).
- The **envelope** layout (`env:30-46`) and the **`Blob` / `Attachments`** types and their published
  form (`types:75-400`).
- **The meaning of reserved attachment keys** and **of schema metadata keys that are not data model**
  (`fletcher.row_index*`) (owner rulings 2026-11-10, [RIX-rulings](../../plans/RIX-rulings.md)).

**Refuses:** schema transport, `__schema`, conflict refusal (domain 3); per-transport framing such as
the Fast DDS CDR `sequence<octet>` wrapper and payload bounds (domain 4); WebSocket frames (domain 5);
windowing and loss accounting (domain 7); writing, checking and delivering the row index (domain 8);
keys generated from a `.proto` (`proto_package`, `proto_message`, `field_number`, `field_id`,
`metadata_from_option` keys: domain 1). It does not validate UTF-8, field nullability, or attachment
counts and sizes beyond the buffer (findings A7, C4).

## 2. Ubiquitous language

| Term | Definition |
|---|---|
| **Row** (`EncodedRow`) | The positional encoding of one record against one Arrow schema (`types:22`, `codec.hpp:19-35`). |
| **Positional encoding** | Fields in schema order, no tags, field numbers or schema hash; layout fully fixed by the field types. |
| **Null bitfield** | `ceil(n/8)` bytes, LSB-first, bit set = null, payload omitted (`pio:43-57`). Leads every row, struct, list, fixed-size list and map-value run. |
| **Payload** | The bytes of one non-null field or element. *Also* used by domain 4 for the whole envelope body (`max_payload_bytes`): finding L-1. |
| **Envelope** | `[ROW_LEN:4][ROW][ATT_COUNT:4]{[KEY_LEN:4][KEY][BLOB_LEN:4][BLOB]}*`, u32 LE (`env:30-46`). Fast DDS calls its copy the "envelope body" (`fdds-env:34`). |
| **Attachment** | One key/`Blob` entry carried beside a row. Also called "side data" (PDA-DEC rulings 2026-09-06) and "sidecar data" (`types:127`): finding L-2. |
| **Key** | An attachment's byte-string name; never contains `0x00`; UTF-8 by convention only. Rulings call it a "label". |
| **Blob** | `{owner, data, size}`; owner keeps bytes alive; immutable; empty = null+0 (`types:75-125`). |
| **Published form** | The one enumeration of `Attachments`: ascending unsigned-byte key order, one entry per key (`types:137-163`). |
| **Reserved key** | `[designed-not-built]` An attachment key whose first byte is `0x01`; Fletcher's alone. |
| **Row-bookkeeping attachment** | `[designed-not-built]` The reserved attachment `"\x01f"` carrying a row's index and writer hash. |
| **Schema metadata key** | A key in an Arrow schema's (or field's) key/value metadata. Never a field; never in row bytes (L1). |
| **Fletcher metadata key** | `[designed-not-built]` A schema metadata key that is not data model: `fletcher.row_index`, `fletcher.row_index.writer`. |

## 3. Invariants and laws

**L1. Row bytes depend only on the field types in order and on the values.** Field names,
nullability flags and schema/field metadata never move a row byte. `[built]`
- Holds at: `codec.hpp:32-35`; `codec:620-660` reads only `field(i)->type()` (names only in error
  text); no metadata access anywhere in `arrow-bridge/src` (grep). This is what lets L17/L20 add
  metadata without touching rows.
- Tests: no test (no test varies names or metadata and compares bytes).

**L2. Every encoder of the row format produces byte-identical rows for the same schema and values.**
`[built; the TS encoder is held to it by test only]`
- Holds at: one C++ writer, `PositionalWriter` (`pio:39-156`), used by both `Codec::EncodeRow`
  (`codec:630`) and generated classes (`protoc/src/generator.cpp`). Independent: `gateway-client-ts/src/codec/positional-encoder.ts`.
- Tests: `CodecTest.EncodeMatchesPositionalWriter_*` (`arrow-bridge/tests/test_codec.cpp:841-1339`);
  `integration-tests/protoc-arrow-bridge` (generated `Encode()` == `Codec::EncodeRow`, its README);
  `protoc-gateway-client-ts/test/byte-compat.test.ts:102`.

**L3. A decoder refuses a row that does not match the schema, including trailing bytes.**
`[built for Codec::DecodeRow and BatchDecoder; violated on generated C++ decoders and TS decodePositional]`
- Holds at: `codec:690`, `bd:309`. `PositionalReader::VerifyFullyConsumed` exists (`pio:402`) and its
  comment says generated constructors "should call" it; they do not (`protoc/src/generator.cpp:833-837,860-864`).
  `positional-decoder.ts:314-330` never checks the end either.
- Tests: `CodecTest.DecodeRejectsTrailingBytes`, `BatchDecoderTest.TrailingByteLeavesStateUnchanged`,
  `PositionalIoTest.VerifyFullyConsumedRejectsTrailingBytes`. No test on the generated or TS paths.

**L4. A malformed row is refused, never read out of bounds or half-applied.** Every wire-supplied
count and length is bounded by the remaining buffer before use. `[built]`
- Holds at: `pio:315-320,364-386,438-455`; `arrow-bridge/src/row_reader.hpp`; `BatchDecoder::Append`
  appends nothing on failure (`batch_decoder.hpp:46-49`).
- Tests: `PositionalIoTest.Oversized{List,Map}CountRejected`, `CodecTest.DecodeRejects*`,
  `Fuzz.DecodeRowSurvivesRandomTruncatedBuffers` (`test_codec_property_fuzz.cpp:302`),
  `BatchDecoderTest.Malformed*LeavesStateUnchanged`.

**L5. Null is a bit, not a value.** A null field or element contributes a bit and no payload; map
keys are never null. `[built]`
- Holds at: `pio:43-57,110-148`; `codec:267,372` (null map key refused).
- Tests: `CodecTest.NullFields`, `NinePlusFieldsUseMultiByteNullBitfield`, `MapEncodeRejectsNullKey`,
  `BatchDecoderTest.NullSlotsAtEveryLevel`, `CodecEdge.WideNullBitfieldHighIndexNullsInListAndRow`.

**L6. Little-endian, u32 lengths; nothing larger than 4 GiB is written.**
`[built for the row codec; unchecked on envelope encode]`
- Holds at: `static_assert` `pio:32`, `env:21`, `fdds-env:29`; `CheckCountFits` `codec:49-52`.
  `SerializeEnvelope` narrows `size()` to `uint32_t` with no check (`env:68,72,76,78`), as does
  `EncodeEnvelopeBody` (`fdds-env:39-52`; bounded in practice by domain 4's payload bound).
- Tests: no test for the ceiling on either path.

**L7. A dictionary field travels as its value type; indices never cross.** `[built]`
- Holds at: `codec:296-303,641-652`; re-fold in `BatchDecoder::Finish` (top level only, `batch_decoder.hpp:28-40`).
- Tests: `CodecTest.DictionaryFieldTransfersValueType`, `DictionaryScalarEncodesResolvedValue`,
  `BatchDecoderTest.TopLevelDictionaryRefolded`, `NestedDictionaryRejectedAtConstruction`.

**L8. Batched decode and per-row decode agree for every schema both accept.** `BatchDecoder` may
refuse more schemas (nested/ordered dictionaries), never decode differently. `[built]`
- Holds at: `batch_decoder.hpp:23-41`; both share `detail::Reader` (`row_reader.hpp`).
- Tests: `BatchDecoderTest.MatchesDecodeRowForEveryShape` (`test_batch_decoder.cpp:69`).

**L9. The codec is unaware of attachments, and the envelope is unaware of the row's contents.**
`[built as a property; no code owner]`
- Holds at: no reference to `Attachments` or the envelope in `arrow-bridge/` or `pio` (grep); the
  envelope treats ROW as opaque bytes (`env:67-69,147-151`; `fdds-env:36-39` takes a `RowEncoder`).
- Tests: no test (structural, by include graph).

**L10. One envelope layout frames a row with its attachments wherever a single byte stream is needed.**
`[built; answered in three places]` (finding B1)
- Holds at: `SerializeEnvelope`/`DeserializeEnvelope` (`env:48-220`, used by XRCE and the gateway);
  `EncodeEnvelopeBody`/`ParseEnvelopeBody` (`fdds-env:34-116`); `ts-env:26-108`. In-process uses none.
- Tests: `EnvelopeTest.Roundtrip*`, `ThrowsOnTruncated*` (`core/tests/test_envelope.cpp:61-186`);
  `EnvelopeCodecTest.MalformedBodiesAreRefusedAndLeaveAttachmentsEmpty`. No test compares the two C++ encoders' bytes.

**L11. The same message produces the same bytes: attachments go out in ascending unsigned-byte key order.**
`[built for C++ encoders; violated on TS serializeEnvelope]` (insertion order, `ts-env:30-63`; the wire spec says so)
- Holds at: `Attachments` has one, sorted, enumeration (`types:137-150,205-222`).
- Tests: `SeamVocabulary.TheSameMessagePublishesTheSameWireBytes` (`seamvoc:950`),
  `EnvelopeCodecTest.TheSameBodyIsEncodedToTheSameBytes`, `SeamVocabulary.AnAttachmentSetIsReconstructibleFromItsPublishedFormAlone` (`seamvoc:736`).

**L12. Decoders match attachments by key, never by position; one entry per key, last wins on the wire.** `[built]`
- Holds at: `types:154-155,253-259,370-390`; TS `Map.set` is also last-wins (`ts-env:104`).
- Tests: `EnvelopeTest.ADuplicateAttachmentKeyOnTheWireResolvesLastWins` (`test_envelope.cpp:250`).

**L13. An attachment key never contains a zero byte.** Attaching one is a caller fault
(`kInvalidArgument`); receiving one is a wire fault that drops the message without an exception in
a transport frame. `[built for C++; violated on the TS client]` (`TextEncoder` emits `0x00`; wire spec acknowledges)
- Holds at: `types:205-213` (`Set`), `types:350-352` (`AttachmentsWireBuilder::Append`), `env:188-190`, `fdds-env:111`.
- Tests: `SeamVocabulary.AnAttachmentKeyThatWouldTruncateIsRefused` (`seamvoc:873`),
  `EnvelopeCodecTest.AnArrivingAttachmentKeyWithAZeroByteIsDroppedAsMalformed`,
  `FletcherSamplePubSubTypeTest.ASampleWithAZeroByteAttachmentKeyIsRejected`.

**L14. A Blob always has an owner for its bytes; bytes are immutable; empty is null and zero.** `[built]`
- Holds at: `types:92-115` (refuses null-owner and null-data forms; normalises empty).
- Tests: `SeamVocabulary.BlobRefusesBytesNothingOwns` (`seamvoc:187`); `test_envelope.cpp:121` (empty blob → `nullptr`).

**L15. Decoding an envelope copies no attachment byte.** Blobs alias the received buffer through a shared owner. `[built]`
- Holds at: `env:112-196` (3-arg form), `env:206-212` (one copy, only when attachments exist), `fdds-env:108-109`.
  `Envelope::row` is still a copy (`env:150`), stated at `env:118-119`.
- Tests: `SeamVocabulary.BorrowedTransportMemoryCrossesWithoutCopy` (`seamvoc:71`).

**L16. A producer cannot choose the decoder's cost.** Any wire key order decodes in O(k log k). `[built]`
- Holds at: `AttachmentsWireBuilder` (`types:330-397`). The count itself is unbounded by design (`types:189-193`).
- Tests: `EnvelopeTest.ADescendingAttachmentKeyOrderDoesNotMakeDecodeQuadratic` (`test_envelope.cpp:213`).

**L17. Row bookkeeping changes neither the envelope nor the row format.** `[designed-not-built]`
- Source: RIX ruling 2026-11-10 "Option A, no wire-format change"; D-RIX-1, D-RIX-2 ([RIX-row-index](../../plans/RIX-row-index.md)).
  Today's rules already admit the key `"\x01f"` (L13 refuses only `0x00`).
- Proof planned: RIX S5 "payloads are byte-identical to an unindexed topic apart from the attachment".

**L18. Attachment keys whose first byte is `0x01` are Fletcher's; a caller may not set them.** `[designed-not-built]`
- Source: RIX plan §"Per-row value"; ownership: RIX ruling 2026-11-10 "domain 2 owns reserved keys".
  Planned refusal: `Publisher::Publish`, `kInvalidArgument`; `Attachments` itself unchanged.
  Today `Publisher::Publish` forwards attachments unchecked (`pubsub/src/publisher.cpp:95-97`).
- Proof planned: RIX S1 "prefix refusal".

**L19. Row bookkeeping travels as one versioned reserved attachment, `"\x01f"`; the version byte comes
first, and a later version extends the blob without a new key.** `[designed-not-built]`
- Layout v1 (17 bytes, LE): `u8 version=1`, `u64 row index`, `u64 writer hash` = FNV-1a 64 of the
  writer id (RIX plan §"Per-row value"; D-RIX-10). Per-row cost 27 bytes. Writing and checking it are domain 8's.
- Proof planned: RIX S1 round-trip and wrong size/version/key refusals.

**L20. A topic's row index is declared by schema metadata (`fletcher.row_index` = layout version,
`fletcher.row_index.writer` = writer id); these keys are metadata, never fields, and are written by
Fletcher, not by users.** `[designed-not-built; violated on pio:158-260 until RIX deletes it]`
- Source: RIX rulings 2026-11-10 "The index is not part of the data model" and "row-index metadata
  keys belong to domain 2"; D-RIX-2. By L1 they cannot change row bytes.
- **The whole `fletcher.` metadata prefix is Fletcher's.** protoc refuses to generate a key with
  that prefix (owner ruling 2026-11-10, "Agree on all points"). That refusal is domain 1's code
  (`protoc/src/option_metadata.cpp:36-38`, which today reserves only the four proto keys), so it is
  an obligation this domain places on domain 1, not code this domain owns.
- **The violation (Findings D1):** `pio:158-260` carries the index as a trailing schema field today.
  The owner has ruled that RIX deletes it (2026-11-10, "1. (a) RIX should delete them").

## 4. The interface

| Surface | Who may call |
|---|---|
| `PositionalWriter`, `PositionalReader`, `WriteBuffer` (`pio`, `write_buffer.hpp`) | Generated C++ classes (domain 1), `Codec`. Applications only through generated code. |
| `Codec::EncodeRow/DecodeRow` (`codec.hpp:45-68`) | Arrow tier (`PublisherArrow`, `SubscriberArrow`), applications with an `arrow::Schema`. |
| `BatchDecoder` (`batch_decoder.hpp`) | Domain 7 (`RecordBatchBatcher`) only. |
| `Blob`, `Attachments::{Set,Find,KeyAt,ValueAt,size}` (`types`) | Anyone above or below the seam; the seam's crossing type (seam §3.2). |
| `internal::AttachmentsWireBuilder`, `internal::EnvelopeAttachmentCount` | Envelope decoders only (`types:315`, `env:91-97`). |
| `SerializeEnvelope`, `DeserializeEnvelope` (`env`) | Byte-stream transports (XRCE, gateway). Fast DDS uses its own copy (B1). |
| `AppendTrailingUint64Field`, `ReadTrailingUint64Field` (`pio:158-260`) | Public. In this repo only tests call them, but Monorepo calls them in production (`data-acquisition.drivers/modules/RowBatcherFletcher/src/FletcherRowCodec.cpp`; also SurgeIngest `rowbatcher/IRowCodec.hpp`). **Deleted by RIX** (D1). |
| Reserved keys, Fletcher metadata keys `[designed-not-built]` | Set only by `Publisher` (domain 8 code), read by domain 7/8 code and the raw-tier parse helper. |

## 5. Decisions of record

- **2026-09-06, zero-byte key refused when attached** (PDA-DEC-rulings:759) and **on arrival too**,
  without an exception in a transport frame (PDA-DEC-rulings:816). → L13.
- **2026-08-31, zero-copy is required for rows and attachments** (PDA-DEC-rulings:39). → L15.
- **Wire format does not change** (round-scoped): PDA-decouple locked decision 13
  ([PDA-decouple-locked-decisions](../../plans/PDA-decouple-locked-decisions.md):107), PDA-ABI 14,
  GIR 2 with the `Encode()==EncodeRow()` oracle ([GIR-locked-decisions](../../plans/GIR-locked-decisions.md):17). → L2.
- **2026-11-10 (RIX):** index not data model; option A, no wire-format change; domain 2 owns the
  meaning of reserved keys; row-index metadata keys are domain 2's; 8-byte writer hash
  ([RIX-rulings](../../plans/RIX-rulings.md)). → L17-L20.
- **2026-11-10 (RIX):** RIX deletes `AppendTrailingUint64Field` / `ReadTrailingUint64Field`
  ([RIX-rulings](../../plans/RIX-rulings.md), "1. (a) RIX should delete them"). → L20, Findings D1.
- **2026-11-10, ownership, all agreed** ([RIX-rulings](../../plans/RIX-rulings.md), "3. Agree on
  all points"):
  - this domain owns how Arrow types become bytes; domain 1 owns how proto types become Arrow types;
  - `max_payload_bytes` is domain 4's;
  - protoc refuses `fletcher.`-prefixed metadata keys (→ L20);

  class, not an instance (PDA-DEC-rulings:529). L18 follows the same shape.

## 6. Relationships

- **Domain 1** generates code that calls `PositionalWriter/Reader` and so inherits L2-L5; it owns
  the proto → Arrow mapping and proto-derived metadata keys. Its decoders are where L3 is violated.
  `protoc/src/option_metadata.cpp:36-38` reserves only `proto_package`, `proto_message`,
  `field_number`, `field_id`, so a `metadata_from_option` rule could emit `fletcher.row_index` (Q3).
- **Domain 3** carries schemas (with all metadata) over `__schema` and compares their bytes; L20's
  keys reach the conflict check through it, and domain 3 does not interpret them. The seam's
  crossing types `Blob`/`Attachments` are defined here and frozen in seam §3.2.
- **Domain 4**: XRCE uses `env` directly; Fast DDS keeps its own envelope codec inside a CDR
  `sequence<octet>`; both put the `max_payload_bytes` attachment on `__schema` (below).
- **Domain 5**: the gateway re-frames envelopes (`gateway/src/ws_session.cpp:213,279`); the TS client
  is a second envelope and row implementation, and violates L11 and L13.
- **Domain 7** drives `BatchDecoder` and keeps attachments row-aligned; it must not decode.
- **Domain 8** writes and checks L19's attachment and L20's keys; this domain defines what they mean.

**`max_payload_bytes` is not domain 2's.** It is defined in `pubsub/include/fletcher/pubsub/payload_bound.hpp:73-76`
(`kSchemaPayloadBoundKey`), set only by the DDS providers on the `__schema` announcement
(`fast_dds_pubsub_provider.cpp:959`; `xrce_dds_pubsub_provider.cpp:931,1338`) and read only there
(`:382`; `:311`). Its meaning is "open your data reader at this DDS type bound" (`payload_bound.hpp:62-68`),
which is transport-type matching: domain 4's, under a convention domain 3 hosts. Domain 2 owns only
that it is a well-formed attachment. It is not `0x01`-prefixed, so L18 does not cover it, and users
cannot reach it because the `__` segment prefix is refused. Confirmed by the owner, 2026-11-10.

## 8. How to extend this domain

**A new reserved attachment key:** (1) take a key `"\x01" + <one byte>` that is not yet used
(registry: this section; today only `"\x01f"`); (2) define its blob with a leading version byte
(L19 pattern), LE fields, fixed size per version; (3) add a law here marked `[designed-not-built]`
with owner sourcing; (4) state who writes it and who strips it (domain 8 / 7); (5) no envelope
change is allowed (L17). A non-zero-byte key needs no codec change.
**A new Fletcher metadata key:** prefix `fletcher.`; the value is a string with a stated version or
format; never a field (L1, L20). No per-key registration is needed: protoc refuses the whole
`fletcher.` prefix, which is domain 1's obligation under L20. Remember that the key takes part in
domain 3's byte comparison.
**A new Arrow type in the row format:** add a case to `codec` encode and decode, to `bd`, to
`scalar_codec.cpp`, and to the TS encoder/decoder if the gateway carries it; prove it with
`EncodeMatchesPositionalWriter_*`, `MatchesDecodeRowForEveryShape` and the byte-compat suites (L2, L8).

## Findings (reported, not fixed)

**A. Spec or doc against the code**
- A1. The wire spec's payload table omits types the codec carries: decimal128/256,
  fixed_size_binary, intervals, time32/64, large and view string/binary/list, and float16. It also does
  not say that large types still use a u32 `LEN` with a 4 GiB ceiling (`codec:49-52,196-208`).
- A2. `pio:398-401`: "generated message constructors should call" `VerifyFullyConsumed`; they do not (L3).
- A3. `gateway-client-ts/src/wire-types.ts:5` says it mirrors `WireTypeId` in `schema_evolution.hpp`.
  No such file exists. The C++ side is `gateway/src/schema_codec.cpp`.
- A4. The wire spec says attachments "remain a transport-layer concern". By the 2026-11-10 ruling,
  reserved-key meaning is domain 2's (RIX S6 already plans the doc update).
- A5. No document says whether bytes after the last attachment are allowed. All three decoders
  accept them silently (`env:192-195`, `fdds-env:113-115`, `ts-env:105-107`).
- A6. `ParseEnvelopeBody` accepts a body with no `ATT_COUNT` as zero attachments (`fdds-env:89`).
  `DeserializeEnvelope` refuses it (`env:133`). The spec layout makes `ATT_COUNT` mandatory.
- A7. `Codec::EncodeRow` encodes a null into a non-nullable field without complaint (`codec:633-636`).
  The wire spec's nullability rules are not enforced by this domain.
- L-1. "Payload" means field bytes in the wire spec but the envelope body in `max_payload_bytes`.
  L-2. One concept has three names: attachment, side data, sidecar data (plus key/label).

**B. Rules answered in more than one place**
- B1. Envelope encode: `env:48`, `fdds-env:34`, `ts-env:26`. Decode: `env:131`, `fdds-env:64`,
  `ts-env:68`. Shared code covers only `EnvelopeAttachmentCount` and `AttachmentsWireBuilder`. The
  two C++ decoders already differ (A6, and the count bound `fdds-env:94` versus none, `types:175-180`).
- B2. Row decode: `PositionalReader` (generated C++), `detail::Reader` (`row_reader.hpp`, Codec and
  BatchDecoder), `positional-decoder.ts`. Row encode: `PositionalWriter` and `positional-encoder.ts`.
  The bounds checks are re-implemented in each, and they disagree on trailing bytes (L3).
- B3. Arrow type → wire-type id: `gateway/src/schema_codec.cpp` and `wire-types.ts`, kept in sync by hand.
- B4. The proto → Arrow table is in the wire spec and in arch overview §4.2 (Q1).

**C. Behaviour with no test**
- C1. L1: names and metadata do not move bytes. C2. L3 on generated and TS decoders.
  C3. L6: the u32 ceiling on envelope encode.
- C4. A5 and A6 (trailing bytes, missing count). C5. Byte identity between `SerializeEnvelope` and
  `EncodeEnvelopeBody`. C6. A7 (null in a non-nullable field). C7. L9.

**D. Tier-1 conflicts (not resolved here)**
- **D1. `AppendTrailingUint64Field` / `ReadTrailingUint64Field` (`pio:158-260`, from PR #104
  "proposed option for ingest offsets").** This public core API stamps `_ingest_offset` into the
  row as a schema field. Its contract is "decode with a Codec built for the schema that has
  `_ingest_offset` appended as its last field" (`pio:185-187`). That contradicts the ruling "The
  index is not part of the data model" and D-RIX-2 ("no Arrow field"). Its position (last) also
  differs from D-RIX-11 (column 0). Tests pin it: `AppendTrailingUint64FieldTest.*`,
  `ReadTrailingUint64FieldTest.*` (`core/tests/test_positional_io.cpp:86-203`),
  `IngestOffsetTrailingField.*` (`arrow-bridge/tests/test_codec.cpp:752-831`).
  **Resolved 2026-11-10: RIX deletes the helpers.** Their tests' subject is now forbidden, so they are
  **deleted, not re-anchored**. The deletion breaks Monorepo's production callers, so it ships as a
  breaking `fletcher-core` release (0.4). Those callers stay on 0.3 until they move to row
  bookkeeping.
