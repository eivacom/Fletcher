Checked and sound. Lifetime: the release runs only from `TryFree` (behind the interlocked exchange), after `Self.Free`. Every branch that reaches `TryFree` comes after `OnRow` has returned. The delivery branch runs in the thunk's `finally`. The canceller and `Subscriber.Dispose` branches come after a draining native cancel. On the carve-out (a cancel from inside a delivery), a delivery past `TryEnter` frees on `Exit`, and one that has not reached it is refused there. So no decode can overlap the codec's dispose (P2 holds). `Dispose` also sets `_decided`, so if P2 ever broke, the row would become a counted drop, not a decode on a dead codec. A decoded batch is imported through the C Data Interface and owns its memory, so a codec freed after `Unsubscribe` does not invalidate a batch the user kept. `OnRow` has no early exit. Exactly two `BatchStatus` shapes are built. A failed copy or decode disposes the copied attachments. A failed subscribe releases the delivery. Decide-once works as designed: a null schema decides nothing, the first schema decides for good, and a codec that cannot be built latches "none". The forcing test is not vacuous: it checks its own fixture (the reference codec refuses exactly the malformed kinds, the seed contains both kinds each followed by a good row, and the arm-(c) schema is refused by the codec), and it was red first for the right reasons (evidence row). Timing depends only on P4, as the rest of the file does. The leg's `FreedDeferredCount` delta is not racy: the deferred free hits the exchange and records nothing.

## Findings

**S1 - should-fix (confidence high): no test observes the release itself.** This stage's one new lifetime mechanism, the `release` passed to the internal `Subscribe` overload, has no test. The leg brackets `FreedByDeliveryCount` but never sees `RowDelivery.Dispose` run. So a regression in which `TryFree` stops calling `DisposeRelease`, or the failed-subscribe branch drops it, leaks the codec silently, and the suite stays green. The tests already reach internals (`FreedByDeliveryCount`). Fix: call `inner.Subscribe(topic, handler, null, release)` with a counting `IDisposable`. Assert it is released exactly once on each path: drained cancel, self-cancel (delivery branch), sibling cancel (deferred branch), `Subscriber.Dispose`, and a refused subscribe (non-zero `MaxPayloadBytes`). Also assert it is released after the last handler return. This takes about 30 test lines and no production hook.

**N1 - nit (high): `DisposeRelease`'s catch-all is unreachable today, so the swallow is not reachable-and-silent now.** The only release is `RowDelivery.Dispose`: a lock plus `FletcherCodec.Dispose`, which is a flag plus a `SafeHandle.Dispose`, and none of that throws. Prefer the forbidding direction: type the parameter as the one internal release and drop the try/catch, or state "must not throw" on the overload. If the catch stays, make it count (`Diagnostics.CountAbsorbed()`) rather than swallow, so a future release that throws is visible. Note that on a transport thread the thunk's outer catch would contain a throw anyway. The catch only earns its place in `Subscriber.Dispose`'s loop and on the failed-subscribe branch.
**N2 - nit:** in arm (c), the published rows are `TwoColumns` encodings, so the test cannot tell "latched none" apart from "a decode refused per row". Both give the same observable outcome, which is all BC-16 asks for.
**N3 - nit:** the leg reaches `_subscriber` by reflection on a private field name. Expose an internal accessor so a rename fails at compile time, not at run time.
**N4 - nit:** doc bulk is not the overrun. Of 184 added production lines, 44 are comments and 17 are blank, leaving 123 code lines. The excess over the estimate is `RowDelivery` and `CopyAttachments` (a declared duplicate until rung 8), not prose.
