# protoc-dotnet — the generated C# as a consumer meets it

BIND-6's integration test. A .NET test project generates C# from
[`proto/model.proto`](proto/model.proto) with its **own MSBuild target**, compiles it
against **Apache.Arrow only**, and tests what came out. CI runs it as
`ci.integration-test.protoc-dotnet`, on Linux in the devcontainer and on Windows natively.

## What it proves

| Claim | How |
|---|---|
| A consumer can run the generator the way D-BIND-71 says | `ProtocDotnet.csproj`'s `FletcherGen` target runs protoc from an MSBuild `Exec` before compile, with the plugin from `$(FletcherProtocPlugin)`, and adds the generated file to `@(Compile)` inside the target. That is the recipe a consumer writes; once `Eiva.Fletcher.Protoc` exists (BIND-9) it sets the property and this project does not change. |
| The generated model needs nothing but Apache.Arrow (D-BIND-72) | The project references no Fletcher assembly, so the build would fail if the model did; `GeneratedModelTests` also asserts the compiled assembly references none. |
| Every generated `Schema` is the schema C++ generates | `GeneratedSchemaTests` compares each one with the `.ipc` the same protoc run wrote from nanoarrow: names, types, nullability, metadata in order, all the way down. `TheComparisonCanFail` keeps the comparison honest. |
| Rows round-trip through `ToArrow` / `FromArrow` | `ConversionTests`, nulls and extremes included, and the slice boundary: a message with a list, struct or map has its `Schema` but no conversion until BIND-6c. |
| The names follow protoc's rules (D-BIND-69, 70, 73) | Mostly by compiling: `Player_`, `Class`, `Clone_`, `Schema_` and `Player_Mode._2D` are used by name, so a wrong rule does not build. |
| Generated code passes every analyser | `AnalysisLevel` is `latest-all` with warnings as errors; the generated file passes because it opens with an `<auto-generated>` block. |
| Types from another file work across assemblies (BIND-6e, D-BIND-80) | `ProtocDotnetShared` generates [`proto/shared.proto`](proto/shared.proto) and protoc's own `google/protobuf/timestamp.proto` into an assembly of its own, as a consumer's contracts project would; `model.proto`'s `Route` uses those types as a field, a list, a map value, an enum and a list of enums. Its `Schema` is compared with the `.ipc`, it round-trips, and `GeneratedModelTests` pins the topology: the types are in the other assembly, and `ToArrowColumns` stayed internal. Building `Route`'s columns through the other class's internal member would not compile here (CS0117, by mutant). |

Falsified once by hand (2026-10-05): a plugin built with a map key rendered nullable makes
exactly one case fail, naming `Player.tags/entries/key`.

## Running it

```bash
conan create protoc --build=missing -pr:a=<profile>
```

```bash
FLETCHER_PROTOC_PLUGIN=<path to fletcher-protoc> PROTOC=<path to protoc> dotnet test -c Release
```

run from `dotnet/ProtocDotnet`. protoc's well-known types are taken from `../include`
beside the protoc binary, where the Conan protobuf package puts them. Without either
variable the build stops with a message saying which is missing.

The C#-versus-C++ **wire bytes** comparison in BIND-6's acceptance needs the native shim,
and arrives with the native publisher pair (BIND-6d).
